# Known limitations & roadmap

## Known limitations (MVP)
* **Tests not yet executed** — see `TESTING.md`. Run both suites before relying on the build.
* **No real market data yet.** The only populated market data is the SIMULATED demo set. No external source is
  integrated; NarxStat is the recommended first integration once its API docs and terms are reviewed.
* Baseline Alembic migration builds the schema from the ORM; later changes must be explicit revisions.
* PostGIS is enabled but geometry columns are not used yet (region centres + lat/lng numerics; distance is between
  regional centres, so intra-region delivery distance is not modelled).
* Rate limiting is in-process (single API instance). Use Redis for multiple replicas.
* Search uses normalised `LIKE` matching; add PostgreSQL full-text / trigram indexes for scale.
* Assistant intents are a fixed set (cheapest, best total, suppliers, minimum quantity, region comparison, average,
  increases/decreases, regions with most offers, product overview); other questions get an honest “can't map it”.
* Exchange rates are entered manually; no automated Central Bank feed yet.
* UI primitives are hand-written in shadcn/ui style rather than generated by the shadcn CLI.
* Product images are URLs only (no upload pipeline); file uploads are limited to CSV/XLSX imports.
* Tokens are stored in `localStorage`; move to httpOnly cookies + CSRF protection for production.
* Legal compliance (personal data law, medical goods registration, data licensing) has not been reviewed.

## Roadmap
**Phase 1 — Market intelligence foundation (this MVP):** catalog, suppliers, offers, comparison, history, regional
analytics, AI assistant, market data engine, admin.

**Phase 2 — Advanced intelligence:** NarxStat and other permitted integrations, trigram/embedding product matching
with active learning from review decisions, seasonality-aware forecasting, richer supply/demand from completed
transactions, personalised recommendations, alerting on price moves.

**Phase 3 — B2B commerce:** full RFQ with multiple suppliers, negotiation threads, purchase orders, order tracking,
transaction records feeding `verified_transaction` prices, commissions.

**Phase 4 — Logistics & inventory:** warehouse geometry (PostGIS), logistics providers and delivery pricing,
stock synchronisation APIs, shipment tracking.

**Phase 5 — Ecosystem:** subscriptions and billing on the existing plans table, premium analytics, financing and
payment integrations, public API for partners.
